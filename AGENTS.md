# AGENTS.md · Apetit Radar

Orientation for AI agents and reviewers working with this repository: what the system is, how to run and verify it,
and where the evidence for every claim lives. The human-facing overview is [README.md](README.md).

## What this is

Apetit Radar is a traceable climate and sustainability decision system for Apetit Plc (frozen vegetables and rapeseed
oil; contract farms in Finland and Sweden), built for the Since AI Hackathon 2026 challenge *Climate & Nature Navigator*.
It answers the three problems Apetit's team raised:

1. **Scattered, messy data** → Track A: detect and correct data-quality issues across 43 source feeds, with an audit log
   and expert sign-off; rebuild the GHG inventory from cleaned records with record-level lineage.
2. **Reports built by hand** → the inventory, corrections and Excel reports are generated by code, every line traceable
   to source records and emission factors; SBTi targets and pathways from the same base (`src/b_sbti.py`).
3. **Climate surprises like Sweden 2026** → Track C: a parcel-level yield model, a 15-season outlook under three SSP
   paths, € at risk per crop and season, and a plan finder that simulates adaptation options.

A copilot (Track E) sits on top: Ask (answers with record keys and sources), Simulate (a plan through the yield model)
and Teach (notes and decisions filed into a knowledge graph with four-eyes confirmation).

**Data:** the challenge's synthetic twin of Apetit. Figures are not Apetit's real data; the app and outputs say so.

## Verify in five minutes

```bash
pip install -r requirements.txt          # Python 3.11+
make test                                # pytest; tests needing the data pack skip without it
API_MOCK=1 make api                      # FastAPI from committed fixtures, no data pack needed → http://127.0.0.1:8000/docs
```

With the data pack unzipped in `data/` (see [data/README.md](data/README.md)):

```bash
make all                                 # every submission CSV + scores from raw data, ~1 min, deterministic, no LLM key
python -m ccn_tools                      # the organisers' scorer against the public dev keys (run from the pack's tools/)
make snapshot v2 && make api             # real layers
make web                                 # React app on http://localhost:5173
make demo-check                          # the demo flow through the real API, one ok / FAIL line per step
```

## Architecture in one screen

- `src/load.py` loads the pack untouched into DuckDB (`raw_*`, `task_*`).
- `src/a_detect/`, `src/a_triage.py`, `src/a_inventory.py`: detectors, triage, corrections, inventory 2023–25,
  lineage (`src/lineage.py`).
- `src/c_features.py`, `src/c_model.py`, `src/c_ensemble.py`, `src/c_euro.py`: stage-aware weather features, the
  yield model (ridge on log-yield + farm effects + gradient-boosted residual), the SSP ensemble, € risk.
- `src/p_*`: prediction layer (scenarios, plan engine, pathways, presets, weather frames).
- `src/r_*`: retrieval, reports (Excel with a Sources sheet), knowledge items, gaps, cited solutions.
- `src/e_*`: copilot routing and deterministic resolvers; the LLM is optional and never computes a number.
- `api/`: FastAPI (`/api/radar/outlook`, `/api/search` plan finder, `/api/radar/ask`, `/api/simulate`,
  `/api/tacit/*` Teach, `/api/graph`, `/api/report/*`, `/api/sbti/pathway`); OpenAPI at `/docs`.
- `web/`: React + Vite + TypeScript app (Overview outlook, Assistant with Ask / Simulate / Teach, knowledge graph).

## Rules the code enforces

- Deterministic code computes every number; models are evaluated on data they did not see.
- Agents fill `proposed_by`; only a human fills `approved_by`. Results stay draft until a person publishes them.
- Pack guardrails: credit notes net against receipts; vessel lots in tonnes, seasonal meter peaks and ammonia systems are
  not errors; R717 has GWP 0; biogenic CO2 is a memo item; GoOs count only in their vintage year, capped at the site;
  peat soils at 29 t CO2/ha/yr; Foodhills from Dec 2025; grain trade outside the base year; L27 (better measurement) and
  structural changes are never reductions.
- Synthetic results are never presented as Apetit's real figures.

## Working on this repo

Development conventions for the team's coding agents (identity, claims, branches, reviews, protected paths) are in
[docs/AGENT_TEAM_RULES.md](docs/AGENT_TEAM_RULES.md). Commits are signed `[agent-name] message`; never push directly to
`main`; tests that need the data pack must skip when `DATA_DIR` is missing.
